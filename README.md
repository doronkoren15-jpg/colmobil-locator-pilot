# כלמוביל — איתור נקודות מכירה

אפליקציית React + Vite + TypeScript סטטית בעברית ו-RTL. נציג בוחר יישוב, פעילות ומותג ומקבל עד שלוש נקודות מכירה לפי Haversine. המרחק הוא **בקו אווירי מנקודת היישוב**, ולא מרחק נסיעה.

החיפוש מקומי בדפדפן. אין AI, שרת יישומי, מסד נתונים, מפתחות API, מעקב, הרשאת מיקום או פנייה לשירות גיאוקודינג במהלך השימוש.

## הפעלה מקומית

דרושים Node.js (נבדק עם 24.13.0), npm ו-Chrome.

מתוך תיקיית הפרויקט:

```powershell
npm ci
npm run data:build
npm run dev
```

פתחו את הכתובת שמופיעה במסוף, בדרך כלל http://localhost:5173. יש להשאיר את המסוף פתוח. זהו שרת פיתוח מקומי בלבד; הוא אינו חלק מהאפליקציה הנפרסת.

## בדיקות ובניית אתר סטטי

```powershell
npm test
npm run test:e2e
npm run lint
npm run build
npm run preview
```

- `npm test`: בדיקות לוגיקה, CSV, טעינה וממשק.
- `npm run test:e2e`: Chrome מותקן, בהרצה ללא חלון, במחשב ובתצוגת טלפון. הכלי מפעיל וסוגר בעצמו שרת Vite מקומי בפורט 5173. הפורט צריך להיות פנוי; עצרו קודם את `npm run dev`.
- `npm run build`: מאמת וממיר את הנתונים, מבצע בדיקת TypeScript ויוצר `dist`.
- `npm run preview`: תצוגה מקומית של תוצר הבנייה, בדרך כלל http://localhost:4173.

לפריסה עתידית מעתיקים **רק את תוכן `dist`** לאירוח הסטטי הארגוני שנבחר. כתובות המשאבים יחסיות, ולכן ניתן לארח גם בתת-תיקייה. אין צורך בניתוב שרת מיוחד. אין לפתוח את index.html באמצעות file://; יש להגישו דרך HTTP. לא בוצעה פריסה במסגרת העבודה.

## מצב המאגר בעת המסירה

נקראו כל חמשת הקבצים בארכיון המקורי. לאחר מכן נאספו כל הרשומות שהופיעו ברשימות החיות של שמונת מותגי הרכב החדש, טרייד וטרייד יוקרה. קיימות 126 רשומות רכב חדש לפני איחוד מותגים; 15 רשומות טרייד חיות וחמש רשומות יוקרה. רשומת טרייד חולון ההיסטורית נשמרה בנפרד כטעונה אימות.

אין לראות בספירת רשומות ממקורות אינטרנטיים אישור לשלמות ארגונית. בדפי זכייני JAECOO ו-OMODA באילת התגלו סתירות טלפון; שתי רשומות המותג הוחרגו מהדירוג. נקודות יישוב חסרות וחשדות לכפילויות מפורטים בדוחות.

המאגר כולל 1,316 שמות יישובים מרשות האוכלוסין, עם 1,264 נקודות מייצגות שהושלמו לפי סמל יישוב מהלמ״ס 2023 והומרו מ-ITM ל-WGS84. ל-52 רשומות אין נקודה תואמת; ניתן למצוא את היישוב, אך לא לקבל ממנו דירוג עד השלמתה. שנת המקור היא 2023, גם כשהבדיקה בוצעה ב-2026.

מיקומי הסניפים התקבלו מקישורי Waze רשמיים ונבדקה התאמתם לרשומת הכתובת ולתחום היישוב. לא בוצעה מדידת GPS בשטח או שיחת ניסיון למספרים. כל הפרטים מסומנים לפי שיטת האימות המתועדת.

פתחו באפליקציה את **״מקורות ומצב הנתונים״**, או קראו:

- `reports/data-gaps.md`: דוח הכיסוי, שיטת האימות והפערים.
- `reports/source-records.csv`: הרשומות המקוריות, כתובות, פרטי קשר, מקורות וניווט.
- `reports/location-merges.csv`: ראיות לאיחוד רשומות לאותו מיקום.
- `reports/source-conflicts.csv`: סתירות פרטים שנמצאו במדגם דפי הסניפים.
- `reports/possible-duplicates.csv`: אתרים בכתובות שונות סמוכות שדורשים בירור זהות, ללא איחוד אוטומטי לפי קרבה.
- `reports/official-validation.json`: דוח תקינות ונתונים המוחרגים מהדירוג.
- `data/sources`: צילומי הנתונים הגולמיים מן המקורות, כולל בדיקות דפי סניפים שנשמרו.

## עדכון סניפים ויישובים

1. ערכו את `data/official/localities.csv`, `locations.csv` ו-`offerings.csv`, בהתאם ל-`docs/data-model.md`.
2. שימרו מזהים קיימים. אתר פיזי מקבל מיקום אחד; כל קשר מותג–פעילות מקבל רשומה משלו. אין להסיק טרייד/יוקרה ממותג, ואין להסיק זמינות מותגים ממלאי משתנה.
3. שמרו מקורות ותאריכי בדיקה. השאירו נתון חסר ריק; אל תכניסו אפס במקום קואורדינטה. אל תסמנו `verified` ללא בדיקת מקור והתאמה. נקודה מאומתת דורשת מקור, שיטה ותאריך.
4. הריצו `npm run data:build`, בדקו את הדוחות, ולאחר מכן בדיקות ו-Build.
5. שמרו את העדכון בהיסטוריית גרסאות לפני החלפת האתר הסטטי.

ה-JSON והדוח שבתיקיית `public` נוצרים אוטומטית. אין לערוך אותם ידנית. נתוני ההדגמה נמצאים ב-`data/demo`, נפתחים רק לפי בחירה ומסומנים כסינתטיים; חיוג וניווט מושבתים במצב זה.

## גיאוקודינג אופציונלי בשלב הכנת נתונים

לא היה צורך לבצע גיאוקודינג חיצוני ל-146 הרשומות החיות, משום שלכולן פורסמו קואורדינטות ניווט רשמיות. כלי הכנת נתונים נמסר לצורך בדיקה חד-פעמית של כתובות סניפים חסרות בעתיד:

```powershell
npm run data:geocode -- LOCATION_ID
```

יש להחליף LOCATION_ID במזהה קיים מתוך locations.csv. הכלי מקבל עד 20 מזהים מפורשים, שולח בקשות בתהליך יחיד וממתין לפחות שתי שניות ביניהן. הוא שומר תשובות במטמון ומפיק **מועמדים לא בדוקים בלבד** ב-`reports/geocoding/candidates.csv`; הוא אינו משנה את קובצי המקור ואינו מסמן אימות.

לפני שימוש יש לקרוא את [מדיניות Nominatim](https://operations.osmfoundation.org/policies/nominatim/): אין הרצות מתוזמנות, אוטוקומפליט, פיצול לכמה מכונות או בקשות חוזרות ללא שימוש במטמון. השירות מוגבל; יש לעצור בעת שגיאה. הנתונים הם © OpenStreetMap contributors, ברישיון ODbL; כשמוסיפים תוצאות למאגר יש לשמור מקור וייחוס מתאים.

תוצאת גיאוקודינג מחייבת השוואת היישוב, הרחוב ומספר הבית לכתובת הרשמית. תוצאה עמומה, כללית או סותרת נשארת `candidate` או `conflict`, ואינה מדורגת. אין לשנות `verified` באופן אוטומטי.

## מבנה הפרויקט

`src/components` — שדה היישוב וכרטיס תוצאה; `src/lib` — מודלים, אימות, טעינה ולוגיקה טהורה; `data` — מקורות CSV ותיעוד מקור; `scripts` — המרה, דוחות וגיאוקודינג להכנת נתונים בלבד; `tests` — בדיקות יחידה וממשק; `e2e` — בדיקות Chrome; `public` — קובצי הנתונים והדוח הנמסרים לאתר; `dist` — תוצר הפריסה.

המסירה נבדקה בפועל כמפורט ב-`reports/verification.md`. אין התחברות, CRM, מפה, ניהול מלאי או מערכת ניהול במוצר זה.

## עדכונים דרך GitHub ו-Netlify

הריפו המיועד הוא https://github.com/doronkoren15-jpg/colmobil-locator-pilot, והאתר הקיים הוא https://colmobil-locator-pilot.netlify.app. יש לחבר את הריפו לפרויקט Netlify הקיים כדי לשמור על כתובת האתר.

הקובץ `netlify.toml` מגדיר Node.js 24, יצירת נתונים, בדיקת קוד, בדיקות אוטומטיות ו-Build, ולאחריהם פרסום תיקיית `dist`. Netlify תפרוס אוטומטית אחרי push לענף `main`, לאחר שיחובר לפרויקט כענף הייצור. Build שנכשל אינו מחליף את האתר הפעיל.

בסיום שינוי בקוד או ב-CSV, יש לבצע commit ו-push ל-GitHub. שמירת קובץ במחשב כשלעצמה אינה מעלה אותו ל-GitHub. שינויים באתר החי אינם נמשכים חזרה לקוד. אפשר להמשיך לעדכן כאן את הפרויקט ולפרסם שינויים שהושלמו באמצעות Git.

אין להעלות `node_modules`, תיקיית `dist`, מפתחות או קובצי הגדרות התחברות. קובצי הנתונים ב-`public/data` והדוח `public/data-status.html` נוצרים מתיקיית ה-CSV לפני הרצה או פריסה, ולכן אינם נשמרים בריפו. לאחר שכפול חדש יש להריץ `npm ci` ואז `npm run data:build` לפני `npm test`.
